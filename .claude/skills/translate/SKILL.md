# Translate

How it works: `i18n/i18n.js` finds every Russian string of the script, grouped by the top-level declaration it lives in,
and swaps it for the translation from `i18n/tables/<lang>.json`. Those tables are generated by the build from the done
batches plus the fixes you write:
- `i18n/fixed.json` — `{group: {russian: [english, portuguese]}}`
- `i18n/de/fixed_de.json` — `{group: {russian: german}}`

## Steps
1. `./build/build_all.sh` → `i18n/out-{en,pt,de}.html.missing.json` list what is untranslated: `{group: [russian…]}`.
   Baseline, always there, leave alone: GAMES 1, LEARN_IMG 3, SND_HI 4 (= «missing 8 in 3 groups»).
2. Write the translations into the two fixed files (copy `i18n/fix_example.py`: a dict `W = {russian: (en, pt, de)}`
   applied to every missing group). Many strings (>100) → the `translator` subagent with the list and this skill.
3. `./build/build_all.sh` again until each language says «missing 8 in 3 groups».

## Style (full guides: `i18n/GUIDE.md`, `i18n/de/GUIDE_DE.md`)
- EN: simple, warm British English (colour, maths, Mum), short sentences a 5-year-old understands.
- PT: European Portuguese only (ecrã, telemóvel, autocolante — never Brazilian).
- DE: simple, warm, du-form for children.
- Keep every `{0}`, `{1}` (they are `${…}` in the source) exactly as many times; keep HTML tags, attributes, emoji.
- Code-like text (CSS, ids, regex pieces, single letters) → unchanged.
- Speech-sound games: the target language's own letters and words for the sound (the R sound, o som do R).

## Content that is not a translation
- `LX('NAME', default)` holds language content (word lists, stories): other languages take NAME from
  `i18n/phonics/{A,B,C}.{en,pt}.json` and `i18n/de/langdata_de.json`. Russian-only content (e.g. MORE_STORIES):
  NAME = `{}` or `[]` there — the strings inside LX() are not extracted at all.
- Russian letters used as data in code (phonetics) → wrap them: `RU('л')`, or the translator will "translate" them.
